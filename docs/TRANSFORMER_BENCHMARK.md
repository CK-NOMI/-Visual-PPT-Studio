# Transformer 真实高密度样本：复现和验收

源图：`samples/S001_transformer_reference.png`，分辨率 **1672×941**，只有 **1 页**，包含 Transformer 编解码器、Self-Attention、Multi-head Attention、Positional Encoding、优势和对比等多个嵌套信息面板。

## 为什么 v0.2 对这张图效果不理想

1. 默认 `elements = [title, body]`，只覆盖原始图很少的文字，不能把完整信息图真正还原成可编辑模块。
2. OCR 文字不是真实作者文字的可信来源，而且对细密中文表格、下标、公式容易把文本错误分词。实际 Tesseract 实测识别 **170 组**文本区域，并发现空格和噪声。
3. 若直接把 OCR 的全部框用于背景修复，mask 容易误伤复杂图形、箭头、边框，结果比原图丑。
4. 保留含有字的原图作为底图、再叠加原生字会形成重影。v0.3 只允许所勾选区域先修复再生成原生文本。
5. v0.2 的预览曾可能滞后于当前内容，且默认依赖 npm。在 v0.3 中已引入修订版校验和 Python 原生 PPTX 编译。

## 执行方式

```bash
# Python 3.11+，项目根目录
python -m pip install -r requirements.txt
python -m pip install -r requirements-dev.txt
python -m pytest -q

# 可选：在 macOS 上安装 OCR：brew install tesseract tesseract-lang
python -m pip install pytesseract

# 不调用 DeepSeek 或 OpenAI，直接对内置真实样本构建一套可编辑PPT
python -m samples.seed_transformer

# 启动 Web 工作台
bash start_mac_linux.sh
```

生成结果在 `workspace/<项目id>/build/`。默认系统调用 `python-pptx` 生成原生文本、形状和独立图片；若电脑安装 LibreOffice，还会获得实际 PDF/PNG 预览。脚本演示自动确认了其中一处局部去字，仅为了重现实验；正式 UI 仍必须人工审核候选。

## 在 Web 界面的正确步骤

1. 「01 内容规划」先创建 **一页**项目；锁定 S001。
2. 「03 编号上传」选目标 **S001**、角色 **design**，上传 `S001_transformer_reference.png`（此方式可由程序自动改名）。
3. 「04+ 重建实验室」点击 **以原图建立基线**。这会清除默认占位标题/正文并备份旧元素；背景与原图一致，但文字还不能编辑。
4. 点击 **OCR 识别并显示区域**。复杂图片可能需要十几秒，结果有中文断词，请人工检查。OCR 结果默认**全部不提升**。
5. 建议先只勾选一个短标题，人工纠错后在「②」保存区域。
6. 「③」选择 `ink`、`OpenCV Telea`，先生成 Mask 和候选底图。务必查看“原图 / 候选”的**局部放大对照**。出现文字残影、渐变断层、网络线条破坏，则**不要确认**；可调整框、尝试 LaMa，或直接手动上传 ChatGPT 编辑过的 clean。
7. 只在候选图满意时点击 **确认候选 → S001_clean.png**；然后点击 **提升勾选文字为原生对象**，在「04 可编辑重建」微调字号、字体和坐标并**保存布局**。
8. 「05」点击质检和可编辑导出；在 PowerPoint/WPS 中双击**刚才确认的那一条文字**，检查文字确实能修改。不要以为所有图中文字都可以修改。

## 已经可确认的真实测试结果

- Tesseract（`chi_sim+eng`, `--psm 11`）在附带图片识别 **170** 个文字组；耗时 ~13 秒（该环境，不能当作 Mac 性能承诺）。
- 演示脚本生成 1 页原生 PPTX；将右上方“更强的表示能力”单独提升为原生文本，结构检查为 1/1 原生文本通过。
- 局部 `ink` Mask 在整页约 **0.216%** 的像素上生效，非 Mask 区域保持原像素；这**并不证明**修复区没有伪影。
- 正式 LibreOffice 渲染后，设计稿与结果的全局绝对 RGB 差异约 **9.1/255**，但这种数值受字体、渲染尺寸影响，也不能证明分层精度。
- **重要缺陷仍存在**：右上文本下面的背景仍有明显模糊，放大看可能出现纹理不连贯。此区域不能称为完全高保真；复杂背景须人工挑选更合适的修复方式，或提交 ChatGPT Image 无字背景。

## 能力边界

本版已经修复主要数据流和工程安全问题，并为复杂图像提供可控的逐层提升机制，但并未实现 SAM 2 全自动物体分层、可编辑数学公式和原生图表自动恢复，也未完成浏览器端全操作 E2E 回归。不会把这三项写成已实现。
