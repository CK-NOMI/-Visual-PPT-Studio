# DeepSeek 成本优化实施记录

日期：2026-10-15。未发起真实 DeepSeek 推理请求或 Files API 上传。

## 已实施

1. **图片复用**：两个同步/异步传输入口接入 Files API。相同原始图片按内容 SHA-256 只上传一次，后续传 file_id；不压缩、不缩小、不删除主 Agent 的整页或局部图。凭据与接口地址共同隔离缓存。远端文件有效期 24 小时，本地提前 5 分钟失效。被删除/过期的引用最多重新上传重试一次。不支持 Files API 的接口回退内嵌图片，并记录回退；HTTP 401/402/403 停止后续调用。
2. **模型上下文**：固定工具 Schema 前置到 system，变化的问题/阶段要求后置到对象数据之后，为前缀缓存保留连续稳定输入。完整本地对象不变，模型收到专用投影。保留文字、原文、公式、rich_runs、位置、样式、实际字体/回退、基线、墨迹边界、溢出和 shaping 信息；去掉本地字体路径/文件哈希和重复身份信息。字体定义与排版字段名去重，采用可还原的列/行表格，缺失值与真实 null 可区分。OCR 证据不再粗暴截成半段 JSON；与原生对象相同的字段通过 element_ref 引用。
3. **历史**：主 Agent 使用各问题最新状态与最近三次精确尝试，省去历史渲染档案；完整本地轨迹不变。独立 Editing Runtime 保留 Design、最新修改前后截图和当前局部图，去掉已更新的旧截图；assistant/tool 顺序、tool_call_id 和 reasoning_content 保留。
4. **计划队列**：模型可以一次提出多个已识别问题的 repair_plans。每项计划绑定所读取对象及同一行关联对象的状态，未变化才复用；发生改变则重新询问。仅缓存可绑定现有对象的 edit/delete/batch_edit，创建或复杂操作沿用原流程。每项实际编辑后仍有真实渲染、DeepSeek 复核；队列结束仍要整页重新检查。离线集成样本中，两项修复由五次模型请求变成四次，两个修改后的复核及最终整页检查均保留；不代表真实页面必定达到同样比例。
5. **无进展保护**：同一目标连续两次没有实际修改，或候选状态反复往返而视觉未通过，暂停该项并保存证据。其余独立问题可继续；未解决项不能伪装成已修复或通过最终交付。
6. **费用保护**：主 Agent 和 Editing Runtime 默认每次任务 ¥1 已知费用、12 次推理请求、64 MiB 请求/上传内容预算。前端可调整。预算也计入 JSON 重试和失效引用重试；两次费用未知后停止继续消费。401/402/403 阻断同任务后续请求。请求取消/超时记录为用量未知，不当作免费。
7. **可恢复暂停**：保存最新已验收候选，撤回尚未视觉复核的本轮变化；新增“从候选继续修复”入口。续修沿用该页候选和问题清单。若只缺最终视觉审阅，单独补做；不能因为预算用完而跳过审阅、声称交付成功。跨项目/页面/基础版本的校验继续生效。
8. **可视化**：增加费用/请求/传输预算设置、运行中用量与暂停原因，以及用量面板的上传量、引用/复用次数、避免的内嵌图片载荷和回退提示。字节是应用层载荷，不能当作官方 Token 或运营商账单。

9. **反思轮次按问题裁剪文字上下文（本次补充）**：针对单个问题做修改后复核时，仍传入整页 Design、修改前后完整渲染及该问题的放大对照；只把 OCR 和对象排版参数限制到问题框及其附近对象/同一文本行。诊断与最终整页审阅仍传完整上下文。若问题框无效或找不到相关对象/证据，自动回退完整上下文，不以缺失证据继续判断。

费用阈值依据请求完成后的真实 usage，单个在途请求仍可能超过设定金额；未知费用也不能算零。12 次请求上限用于控制本次开销，用户主动续修会产生新的预算，不代表整套 PPT 的总金额保证。

## 独立回退开关

- `PPT_STUDIO_IMAGE_REFERENCES=0`：使用原内嵌传图。自定义接口默认不启用 Files API；显式为 `1` 可启用。
- `PPT_STUDIO_COMPACT_API_CONTEXT=0`：恢复旧对象上下文与旧截断方式，仅供对照/排障，不建议日常使用。
- `PPT_STUDIO_QUEUED_REPAIR_PLANS=0`：不复用待执行计划，继续逐项询问。
- 预算通过页面或请求字段设置，恢复大额度不会绕过原有真实渲染和交付检查。

模型型号及主 Visual Agent 原有 thinking 设置未降低。新增日志不保存 Key、Base64 图片或完整用户文件内容。
