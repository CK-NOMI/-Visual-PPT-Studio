## 自动修复按钮：AI查漏与候选生成（2026-10-12）

旧按钮只运行确定性检查和候选生成，不调用 DeepSeek，也不自动进入验收；如果没有达到自动修复门槛的动作，用户看到的只有“待检查项”，容易误以为按钮没有工作。现改为“智能查漏并生成修复候选”：每个选中页最多调用 DeepSeek 一次，对照 Design、当前可编辑页渲染、规划原文、OCR和原生对象清单提出漏字候选。

模型只返回文字、区域和证据建议。服务端会复核文本是否对应规划原文或高置信 OCR、Clean 是否有可信去字证据、附近是否已有原生对象、区域是否合法。满足证据门槛才进入现有单行布局与隔离候选流程；混合文字仍由 `text_layout.py` 分框。文字不确定、Clean 残留或已有对象接近时只展示待复核项，不补建、不覆盖。模型失败时仍保留本地确定性修复，并显示失败原因。

候选区现在显示实际动作数、DeepSeek 调用数、提案数及诊断详情。零动作时明确提示原因，不再呈现为无反馈。

真实样本测试于 2026-10-13 使用 S001/S002 各一次 DeepSeek 查漏（共2次），复用返回的候选做浏览器验收，没有重复调用模型。模型提出4项漏字候选和若干复核提醒：S001英文主标题已由确定性OCR流程识别，模型重复建议被去重；S002一条正文被高置信 OCR（0.9956）独立核对后生成候选，浏览器局部差异变差（MAE 46.188 → 59.731），系统已回滚；“研究目标：”因邻近原生对象而转人工复核。另有背景字重与 IdenticalOutputDistribution 两项也因局部差异变差而回滚。
