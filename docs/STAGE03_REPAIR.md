## 当前交互：一键自动流程（2026-10-13）

定向修复卡片现在只有一个主按钮「自动检查、修复、验收并保存」，替代旧的检查、生成候选、浏览器验收、提交四个分开的操作。按钮依次执行证据检查与有限 AI 查漏、隔离候选、浏览器/PPTX 验证；只有 `validated_pending_commit` 才调用已有提交接口，提交前备份、项目版本与候选哈希校验继续生效。验收未通过时候选会保留诊断和回滚记录，原项目不写入；没有通过证据门槛的修复动作时也不会启动无意义验收或提交。

运行期间刷新页面会从 sessionStorage 中的项目与候选标记恢复同一任务，不重复调用 DeepSeek。若用户切换项目，流程会暂停在候选状态；回到原项目后再继续，不会把结果显示或提交到另一个项目。规则审计、PPTX 导出和可选样式诊断仍是单独的辅助工具，不属于定向修复按钮。

本轮验证：前端真实网页的 Playwright 路由隔离测试覆盖了成功提交、验收失败不提交、无操作不验收、刷新后从候选恢复四种路径，浏览器无 JS 异常；全量 pytest 为 121 passed。S001/S002 浏览器回归在隔离副本中完成，PPTX 结构、布局契约和多页保存/刷新流程通过；整页视觉状态仍为 `requires_review`（S001 19 个、S002 35 个 review-only 对象，0 个 hard-failed / visual-error 对象），因此不能将它描述成全部视觉问题已修复。源项目仍为 revision 402，未由这次 QA 覆盖。

## 本轮闭环

第三步最初新增结构检查 → 隔离候选 → 真实浏览器前后验收 → 显式提交；当前网页已将这四个动作串为一个自动流程，底层仍调用原项目 API，不需要外部脚本手工造 PPT。

- Design OCR 必须与当前源图哈希一致；原生对象按照文字与源区域共同匹配。
- 自动补建需要高置信 OCR、规划文字佐证、无部分/重复匹配、配对 Clean 的 OCR 与像素残字检查。
- 未确认 OCR、残字、重复、移出页面等问题先列证据，不能盲目添加或删除。
- 新文字复用 `text_layout.py`。新标题可用局部字形轮廓比较选择实际可用字体，再以源图真实字形范围确定大小与基线。此选择是候选，不保证准确识别原字体。
- 原对象逐字段保持稳定。候选保留原项目、输入图片快照、候选 JSON/PPTX、前后浏览器 HTML/JSON、局部对照及日志。
- 验收同时检查：新增 DOM 可见文字、字形边界、字体加载、无新增严重错误、局部视觉差异改善、PPTX 导出契约。整个页面仍可处于待复核状态。
- 提交前验证源项目版本/内容哈希及候选内容哈希；失败候选不能提交。原项目提交前另存备份。

## AI 权限

DeepSeek 查漏阶段可提出文字与证据区域建议，但不能直接创建或修改项目对象；服务端必须用规划文字、OCR、Clean 与对象位置证据复核。独立的样式校准仍只接受字体、字号、颜色、粗细/斜体建议，不接受模型坐标或文字改写。确定性排版问题由 `text_layout.py` 处理。API 失败、无可执行建议或不确定证据会保留为待复核项，不以固定分数为停止条件。

## 仍未全面实现

本轮自动操作为有证据的缺失原生文字补建。重复对象删除、复杂背景残字修复、既有对象的几何冲突修复仍需人工复核，不能把对应诊断项标为已修复。S002 的可疑 OCR 不是确定缺字，暂不自动补建。视觉样式仍可能不完全一致。WPS 自动化未开发、WPS 兼容性未验收。

## 使用

在第三步选择检查整套或当前页，然后点击「自动检查、修复、验收并保存」。查看完成状态、原稿/修复前/修复后局部图及对象报告。不通过验证的候选不会覆盖项目；项目版本发生变化时需要重新生成候选。

常规浏览器回归：

```sh
.venv/bin/python scripts/qa_runner.py --browser --project 6d57a8e7389d --slides S001,S002
```

新安全测试：

```sh
.venv/bin/python -m pytest tests/test_repair_pipeline.py tests/test_layout_contract.py tests/test_browser_diagnostics.py -q
```

原有测试不修改。旧校准提示词测试要求模型修改框/边距，与新权限不兼容；明确列为本次行为变化，不伪装成原有失败。既有两个失败为不完整导出报告的 mock 与多尺度 OCR 坐标不一致的 mock。
