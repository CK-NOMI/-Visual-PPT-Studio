# VisualPPTStudio v0.3 修复记录

| 问题 | v0.2 风险 | v0.3 处理方式 | 验证 |
|---|---|---|---|
| 高密度页面被盲目 OCR | OCR 错字、断词转成错误内容 | 默认不提升；必须选择和人工校对 | 真图 170 OCR 组 + 自动测试 |
| 原图文字与重建文字重影 | 无 clean 时叠加原生字 | 新增 raster-first，先保真后逐区去字 | 真实 PPTX 检查 |
| 全部文字被移除导致背景破坏 | 大范围掩码可能擦除插画、连接线 | 只对选中区域去字，保存候选与放大检查 | 非 Mask 区像素一致测试 |
| 候选误写正式 clean | 后续破坏无法追溯 | 审核确认，旧底图备份和来源 SHA 校验 | API 测试 |
| 设计图换了底图没跟着换 | 使用过期素材 | 标记 stale，阻止编辑模式导出 | 回归测试 |
| 页面更新但差异热力图仍使用旧渲染 | QA 误报成功 | 导出 revision 比较，删除旧预览 | 回归测试 |
| diff 热力图色值溢出 | uint8 乘法环绕 | 先 float 缩放再裁剪 | 回归测试 |
| Mac npm 报错阻断启动 | Node 依赖可用性问题 | 默认 python-pptx；Node 可选 | 实际 native PPTX/PNG |
| UI 文字预览与 PPT 字号明显不一致 | 以视口 vw 错误换算 | 根据逻辑页面 960pt 采用 cqw | JS 静态检查；实际浏览器待测 |
| 图片素材错页 | 允许以其他 Sxxx 编号引用 | Python 导出按 slide id 二次校验 | 代码和回归测试 |
| 元素保存被 OCR 覆写 | 标题和原始大纲数据失真 | title/body 规划作为可信来源，明确保存时同步 | 旧测试保持通过 |
| 虚假的“全页可编辑” | 栅格文字未报告 | 编辑覆盖统计与显式警告 | QA 报告 |

**性能说明**：小型示例用 17 项测试覆盖基础 API、安全性、OCR 候选、Mask、图层、数据完整性与可编辑输出；单独脚本测试真实 1672×941 图片的 PPTX → LibreOffice → PNG 预览。已验证均以本地 Linux 环境为准；Mac 仍需在用户设备上执行浏览器交互回归。

**许可证**：源码是为本系统独立实现，技术方案调研参考 px-image2pptx（MIT）、AIPPT（Apache-2.0）、imagegen-pptx-pipeline（MIT）、PaddleOCR（Apache-2.0）、IOPaint（Apache-2.0），未复制其源代码。第三方库以正常依赖方式安装，分别遵循自身许可证。
